# ClearX 技术设计

ClearX 当前使用 SwiftUI、Swift Concurrency 和 Foundation，实现只读扫描与会话内存快照。长期持久化与 FSEvents 设计见 [2026-08-03-clearx-design.md](superpowers/specs/2026-08-03-clearx-design.md)，该文档不代表当前运行行为。

## 点击导航的视口稳定性

- 录屏 `20261015175359_rec_.mp4` 显示切换前面列的条目时，整个浏览器横向回退。原实现先删除右侧列，再等待优先级调度和快照查询，最后追加子列；中间态缩短内容宽度，触发滚动容器的偏移钳制。即使禁用显式自动定位，分支变短仍会触发同类回退。
- 本机 OmniDiskSweeper 实测：深层展开后切换前面列的目录，保留横向位置，右侧允许留白；重复点击已选目录取消更深导航，但保留紧邻子列。修复沿用这两点，不改扫描与排序语义。
- 模型在异步等待前一次性替换为新目录的加载槽位，同目录已加载子列直接复用。查询代次继续拒绝过期响应；失败移除占位，后续点击可重试。
- 视图在点击时记录 `max(0, -首列横坐标) + 视口宽度` 作为内容最小宽度，阻止导航缩短内容时回退。该值只保留必要空白，不缓存被移除列；下一次点击重新计算，导航重置或卸载时清空。末列展开的单次最小距离定位及手动横向输入优先规则保持不变。
- 回归验证包括异步加载期间无删列中间态、重复点击保留分页、快速选择拒绝旧响应、失败重试，以及托管 SwiftUI 窗口中点击目录和文件前后的实际横向偏移。
- 2026-10-15 验证：Debug App/测试构建及全部 109 项 XCTest 通过，Release App 构建与 `git diff --check` 通过。托管窗口以 720 pt 视口、700 pt 初始横向偏移验证切换目录、重复点击和选择文件均不回退；末列被遮挡时定位至 876 pt，重置导航后回到 0 且释放留白。测试仅使用内存夹具，未递归扫描真实全盘；首次运行受沙箱 `testmanagerd` 限制，后续获准在沙箱外执行。

## 执行原则

### 根目录首屏与无骨架加载

- 依据 2026-10-15 用户反馈移除列表骨架。原扫描器在根目录尚未枚举时发布空进度，随后仅靠 2 秒周期刷新已写入的条目，导致首列等待及占位闪动。
- 参考本机 OmniDiskSweeper 1.16 ARM64 静态实现：`ODSFile._checkAttributes`（`0x1000038f4`）以 `opendir/readdir_r` 枚举名称与类型创建子节点；`ODSBackgroundFileSizer.sizeFilesInSeparateThread`（`0x1000096e8`）处理后台大小队列；`ODSFileTreeController._childrenForFile:reorder:`（`0x100007bd8`）返回排序后的已发现子项，窗口初始化 `initWithPath:`（`0x10000610c`）调用 `loadColumnZero`。这是静态调用链证据，不等同于测得参考应用启动耗时；使用本机 `otool`/`llvm-objdump` 与 Objective-C 方法元数据交叉定位，未安装或修改参考应用。
- ClearX 不复制其线程或文件元数据实现，只采用条目展示与递归计大小分离的时序。根目录 worker 完成单层枚举、写入唯一 `ScanTreeStore` 并更新目录状态后，立即发布轻量进度，再入队后代；浏览器从同一树查询前 250 行。未开始的目录仍为红色且大小留空，后续按已知大小实时排序。常规进度仍为 2 秒批量刷新，不逐目录触发 UI 更新。
- 单层枚举仍在主 actor 之外、受全局扫描许可约束，包含隐藏项与包目录，并沿用符号链接和挂载点边界检查。没有第二次根目录预扫、额外结果树或持久缓存。重扫有旧快照时继续只展示旧树，不泄漏候选首列。
- `ResultWindowSession` 统一拥有初始列加载时机，视图不再并发启动初始查询。来源解析及无数据的加载列保持空白，不显示骨架、进度转圈或“正在准备结果”页面；只有完整且可读的空目录显示“空文件夹”，未完成、取消或不可读的空列不误报。

### 启动直扫本机磁盘

- 默认 Scene 直接显示本机磁盘结果窗口，异步解析来源后复用 `ResultWindowContainer` 自动启动扫描；不先创建或闪现扫描源选择窗口。
- 本机磁盘固定采用当前启动系统的根目录 URL `/`，由 `SourceCatalog` 校验其目录类型、本地卷属性和文件系统身份。不得采用卷列表首项、卷显示名称、当前工作目录或 `/System/Volumes/Data` 猜测默认来源；校验失败显示错误和重试，不启动其他来源。
- 保留现有 APFS 路径语义：从 `/` 的正常入口访问用户目录，挂载表中的 Data 等入口仍为零大小边界，不放宽扫描器的设备号或挂载点规则。
- 文件菜单提供本机磁盘窗口和其他扫描位置入口；后者按需打开现有扫描源选择窗口，再打开独立结果窗口。不新增扫描源选择界面或扫描引擎。
- 每个本机结果窗口只解析一次来源，重复视图任务不重复创建扫描会话；解析失败仅在用户重试时重新解析。关闭后的取消与缓存释放沿用现有结果会话。
- 托管 XCTest 运行时不创建扫描界面，避免测试宿主自动扫描真实磁盘。测试通过注入来源加载闭包验证首次加载、重复加载、失败、重试与取消；本机来源测试只读取根目录元数据，APFS 边界沿用单层目录与临时夹具测试，不递归扫描真实磁盘。

### 硬链接双口径（2026-10-15）

- 依据用户确认的方案，浏览器显示和排序使用目录内容大小：每个普通文件路径保留 `st_blocks * 512`，后遇到的硬链接不归零；目录按子项内容大小求和。它允许硬链接重复计数，不等同于物理占用或可释放空间。
- `ScanTreeStore` 仅额外保存一个全扫描去重大小标量，沿用临时 `(device, inode)` 集合，只在首次遇到对象时增加汇总；不再把去重后的大小分配给目录。APFS 克隆不按硬链接去重。节点保存 `isHardLink`，首次与后续路径都说明共享文件数据。
- 身份集合仍只保存 `linkCount > 1` 的文件，普通文件直接增加汇总。测试/诊断的节点数组构造入口无法恢复硬链接身份；包含硬链接时必须显式传入 `uniqueAllocatedSize`，否则触发前置条件失败，无硬链接夹具可沿用根内容大小。
- 根分页查询原子返回轻量 `ScanSizeSummary`，含内容大小、硬链接去重大小、扫描中和不完整状态。浏览器只在首列保留该摘要；进度仍只发布计数及失效 ID。工具栏“大小统计”按需展示两种口径及限制，不恢复顶部普通进度或每列底部提示。
- 摘要与页面来自同一显示快照。保留旧完整快照的候选重扫不得替换摘要；取消和局部不可读的首次扫描摘要明确标记部分结果。缓存继续只接纳完整快照，封存只释放临时集合，不丢失汇总标量。
- 不改变目录列举、设备号检查、挂载表精确匹配、符号链接与 `/.nofollow` 路径处理。必须验证模拟 `Users` 与 `System/Volumes/Data/Users` 的重复硬链接入口只遍历前者，而普通兄弟目录中的硬链接均保留内容大小。
- 回归覆盖同目录与跨目录硬链接、正反批次顺序、传播和分页重排、根文件、APFS 克隆语义（不同 inode）、取消/不可读摘要、旧快照与缓存、挂载边界及百万节点首列性能。诊断只读扫描真实 TTVideoEditor，对照内容与去重字节数，不运行真实全盘扫描。

### 扫描与缓存

- MVP 使用 `InMemoryScanCache`，完整扫描结果只保留在当前进程内，不写 GRDB/SQLite；同一扫描源的最后一个窗口关闭后释放缓存。
- 目录枚举使用焦点路径与普通 BFS 两个环形 FIFO 队列；焦点切换时按节点索引懒提升目标目录，随后发现的后代进入焦点队列。连续处理 8 个焦点目录后至少处理 1 个普通目录，避免后台任务饥饿。
- `ScanTreeStore` 是扫描器、浏览器与缓存共享的唯一节点所有者，维护 `[ScanNodeID: Int]` 节点定位索引和 `[ScanNodeID: [ScanNodeID]]` 父子索引。扫描完成后 `ScanResult` 只传递该 actor 引用，不构建第二套完整节点数组。
- 单次 `ScanTreeStore.apply` 先累计直接文件的大小增量，再沿父链传播一次，而非逐文件遍历祖先。不可读标记也传播至祖先，未完成子目录的已知大小立即参与上层展示。目录完成只更新待完成计数，不再提交大小；取消仅标记未完成目录，不能再次累计大小。
- 批次方法不挂起，读者不会观察到中间聚合状态。节点 ID、父子索引和目录完成时机不变。封存时释放目录工作状态和硬链接临时集合，保留双口径汇总。
- 目录列举显式传入空属性数组，不预取未使用的 Foundation 默认属性，元数据统一由 `lstat` 获取。`DirectoryWork` 构造时规范化 URL，队列入队、出队和焦点判断不再重复规范化；焦点路径字符串只在焦点切换时更新。
- 目录列举在 `FileTreeScanner.directoryContents(at:)` 中使用不带目录尾斜杠的 URL，与 `lstat` 的文件系统表示保持一致。本机只读复现表明 `/.nofollow` 是空目录，但 `/.nofollow/` 会枚举根目录；保留目录 URL 的尾斜杠会把第二棵根树错误地放入 `.nofollow` 并重复累计。不按名称屏蔽隐藏目录，普通目录中的 `.nofollow` 仍正常遍历。回归测试只对系统特殊入口做单层枚举，避免故障版本的测试递归扫描全盘。
- 扫描器在根目录第一层枚举完成、子目录入队前立即发布真实条目对应的进度；独立 reporter 每 2 秒从 `ScanTreeStore` 拉取计数与失效 ID，完成或取消时停止 reporter 并立即拉取末帧。进度链路不复制节点数组，UI 只重查受影响的可见列。
- 每列按 250 行分页读取。新增子项或大小变化使对应父子 ID 排序失效；可见列下次查询时按当前大小降序、同大小本地化名称升序惰性排序，未查询目录不提前排序。扫描中加载更多也从零重取已加载前缀，不拼接可能已过期的偏移页；选中状态绑定节点 ID。
- 扫描和内存节点仅保存系统提供的已分配大小；不读取或聚合逻辑大小。
- 不遍历不等于不展示：`ScanTreeStore.apply` 将符号链接、设备 ID 不同的条目以及挂载表精确命中的目录保留为 `.symbolicLink` / `.mountPoint` 叶节点，大小为零且不参与聚合，不加入目录工作队列、不增加待完成目录数，也不因此标记不完整。符号链接优先按链接处理。扫描根独立初始化，因此直接选择 Data 或外接卷作为根仍正常遍历，根下嵌套挂载点仍被排除。
- 每次目录扫描开始时，在全局扫描许可内读取一次完整挂载表，使用 `getmntinfo_r_np(..., MNT_NOWAIT)` 获得独立缓冲并在转换为 `ScanMountPoints` 后释放，避免并发窗口使用 `getmntinfo` 的共享静态缓冲。挂载点集合不能沿用来源列表的隐藏卷过滤；Data 等隐藏入口仍须保留为边界。挂载 URL 和查询 URL 都标准化并去除目录尾斜杠提示，精确匹配而非前缀匹配，不解析符号链接、不重写 firmlink。挂载表读取失败抛错走现有扫描失败提示，不开始目录枚举、不产出可缓存结果；已有完整结果的重扫继续保留旧快照。重扫重新读取挂载表，不缓存到会话层。
- 该策略依据本机 OmniDiskSweeper 1.16（39.0.8）ARM64 静态逆向：`+[ODSDrive _scanDrives]`（`0x1000011a8`）先从挂载表收集路径再过滤隐藏入口，`+[ODSDrive isMountPoint:]`（`0x10000165c`）执行集合精确查询，`-[ODSFile _checkAttributes]`（`0x1000038f4`）对非根目录同时判断设备号和挂载点，边界归零且不调用 `opendir`。ClearX 保留原有扫描根设备号约束，不照搬其父目录设备号比较。实测 `/Users` 与 `/System/Volumes/Data/Users` 具有相同设备号及 inode，单独按设备号不能避免重复扫描。
- 挂载表是扫描开始时的快照，不实时监听挂载变化；扫描中新增且设备号相同的挂载点仍是残余风险。测试使用合成元数据、临时目录和真实根目录及 `/System/Volumes` 的单层列举，验证同设备号边界、祖先大小不重复累计、扫描根例外、嵌套挂载、尾斜杠与路径前缀、多窗口并发读取、读取失败及候选释放，不递归扫描真实全盘。
- 文件系统访问与大小聚合不运行在主 actor；全局最多同时执行 4 个元数据扫描任务。
- 首次不完整结果可以继续浏览但不缓存。已有完整缓存上的重扫使用独立候选树，候选完整时替换，取消、不完整或失败时释放候选并继续显示旧树。

## 结果展示与异常

- 列内布局采用用户于 2026-10-14 确认的“紧凑固定宽度”对比稿：大小区固定 64 pt、左右内边距 4 pt、名称间距 6 pt，名称起点从 110 pt 左移至 74 pt。保留 12 pt 等宽字体、大小右对齐和待计算空白，不随扫描结果伸缩大小区；较长大小文字单行缩放至最低 75%，完整文字仍由悬浮及无障碍说明提供。列宽、分页、选择及扫描状态不变。`ScanPresentationTests` 验证布局参数、多语言单位与不完整后缀的宽度，以及最小列宽下的单行渲染。
- `ScanTreeStore.page` 返回当前页的待计算和估算节点 ID；封存后两者均为空，取消不能继续显示计算中。首扫结束刷新全部已打开列，保留导航；切换到新的完整快照时重置旧节点选择。
- `ScanNodeRowPresentation` 区分尚未开始（空白）、正常零大小、仍在估算及不完整大小。不完整结果采用 OmniDiskSweeper 式的大小后缀 `+`（包括已统计为零时），悬浮及无障碍说明保留“至少”或“大小未知，结果不完整”，不再使用 `≥` 前缀。硬链接显示完整内容大小，说明共享文件数据，不声称不额外占用或可释放空间。
- 挂载点行说明为“挂载点：本次未扫描其内容，不计入扫描大小”；零表示本次计入量为零，不表示该卷实际为空，也不将同设备号的 Data 卷描述为“其他文件系统”。
- 普通扫描计数、路径和“扫描中”标题不展示；工具栏保留取消操作。局部不可读仅标记对应行，不显示列底部提示、不弹逐项警告；列的不完整状态仍保留，避免不可读目录被误标为“空文件夹”。根目录无法列举或扫描源不可用全局提示。取消显示结束状态；被拒绝的重扫明确说明仍显示上次完整结果，旧树不呈现候选估算样式。
- 参考证据：本机 OmniDiskSweeper 1.16 内置 `HelpImages/colors.png`、`BrowsingFiles.html`、`ColorsandStyle.html`，以及 `_childSized:done:unreadable:`、`sortChildren`、大小状态格式分支的静态分析。紧凑单行、扫描中红色及未开始留空据此实现；颜色按用户最新指令改为名称与大小统一着色，扫描中红色、结束后目录绿色、文件正文色，不再按大小量级分色。选中行保留白字，深色模式使用可读的正文色和绿色。异常提示分层、取消和旧快照提示为用户确认的 ClearX 行为，并非声称逐像素复制参考应用。

## 权限与性能

MVP 不启用 App Sandbox，仍尊重 macOS 文件权限和 TCC。会话缓存不写入 Application Support，也不会跨启动保留。跨启动持久化缓存的预算、淘汰与性能目标在该能力重新引入时确定。

### 硬链接双口径验证（2026-10-15）

- Debug App 与测试目标构建通过，完整测试集 100 项通过；Release App 构建及 `git diff --check` 通过。首次 XCTest 因沙箱无法连接 `testmanagerd` 未能启动，获准在沙箱外重跑后通过。
- 新增/更新测试覆盖同目录与跨目录硬链接、单独扫描与父目录扫描的内容大小一致、根文件、反向批次顺序与分页前缀、不同 inode 不去重、取消和局部不可读摘要、缓存身份与旧结果重扫。模拟 `Users` 和 `System/Volumes/Data/Users` 使用同一真实硬链接文件，确认挂载入口无子节点、无内容或去重贡献；原有真实系统入口单层检查与 `.nofollow` 回归通过。
- 优化构建只读扫描本机 TTVideoEditor：9,148 节点，内容大小 7,238,823,936 字节，硬链接去重大小 7,216,525,312 字节，完整结束；耗时 0.271 秒，采样峰值物理内存 10,715,664 字节。该测量不是全盘归属追踪，不声称与所有第三方统计完全相同。
- 同一基准生成器创建 1,001 目录、100,000 文件：首次全量扫描 101,001 节点，耗时 1.002 秒，约 99,821 文件/秒，采样峰值物理内存 61,309,480 字节，两种汇总均为 409,600,000 字节。单次运行且未清除系统文件缓存，不据此宣称性能提升。

### 可重复基准

在仓库根目录编译独立 Swift 基准工具。显式使用 `-O`，避免把 Debug 的 `-Onone` 与发布应用比较；工具不依赖 SwiftUI，不修改真实扫描目录。

```sh
mkdir -p /private/tmp/clearx-benchmark
xcrun swiftc -O -swift-version 6 -parse-as-library \
  -module-cache-path /private/tmp/clearx-benchmark/module-cache \
  ClearX/Domain/ScanSource.swift ClearX/Domain/ScanNode.swift \
  ClearX/Domain/ScanProtocols.swift ClearX/Domain/ScanState.swift \
  ClearX/Services/FileTreeScanner.swift ClearX/Services/ScanTreeStore.swift \
  ClearX/Services/ScanCoordinator.swift ClearX/Services/ScanPerformanceDiagnostics.swift \
  ClearX/Services/InMemoryScanCache.swift ClearX/Features/Results/SnapshotColumnLoading.swift \
  Tools/ScanBenchmark.swift -o /private/tmp/clearx-benchmark/ScanBenchmark
/private/tmp/clearx-benchmark/ScanBenchmark fixture /private/tmp/clearx-benchmark/fixture
/private/tmp/clearx-benchmark/ScanBenchmark scan /private/tmp/clearx-benchmark/fixture
/private/tmp/clearx-benchmark/ScanBenchmark cache /private/tmp/ClearXCacheBenchmark
```

- `fixture` 只接受不存在的目标目录，创建 1,000 个子目录和 100,000 个单字节文件，不覆盖或自动删除已有文件。本次测得文件分配空间约 410 MB。
- `scan` 每次启动新进程、创建新扫描树，输出耗时、节点数、聚合分配字节、状态及每 250ms 采样的进程物理占用峰值。需要阶段日志时另设 `CLEARX_SCAN_METRICS=1`。
- `cache` 不创建磁盘文件，用参数 URL 作为内存树根，构造 1,000,000 个节点并放入会话缓存。计时包括缓存查找、根节点查询、999 个根子项首次排序和 250 行分页，不包括夹具构建和 SwiftUI 绘制，因此不是端到端首屏渲染验收。
- 对比前后版本时使用同一夹具、相同编译参数，交替运行并取多轮中位数。首次全量扫描和文件系统缓存预热后的全量扫描应分开记录，不将会话缓存命中当成扫描加速。

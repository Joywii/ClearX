# 清理功能范围设计

## 当前范围：用户选定项目移入废纸篓

- 仅允许用户主动选择结果项目并二次确认后调用系统 `FileManager.trashItem`；不永久删除、不清空废纸篓、不提权、不在失败时使用删除作为替代。不引入自动清理 Provider。
- 扫描根、卷挂载点及含挂载点目录、废纸篓及其内部内容、系统判定不可删除或无法核实保护条件的项目禁止处理。多选包含任何禁止项时整批置灰，不静默跳过。
- 使用后台 `lstat` 检查原路径入口和设备号/inode，符号链接只操作链接本身。重叠判定解析已有祖先的物理路径，按完整路径组件比较，不以字符串前缀或目录名黑名单猜测权限。
- 活动扫描（包括显示旧结果的候选重扫）与重叠文件操作互斥。打开菜单、确认及执行前重新核实，系统最终调用失败则报告；最后一次检查与系统调用间仍可能发生外部替换，不宣称原子防护。
- 目录操作覆盖全部实际内容，包括未扫描或无法读取内容；确认明确提示风险及废纸篓不立即释放空间。批量失败继续其他项，支持停止剩余操作，不回滚已完成项。
- 成功使相关缓存失效，相关窗口完整重扫；旧快照标记过期直到完整成功。不用节点大小减法推算释放空间。

## 后续自动清理约束

- 默认仅预选低风险项，高风险项只展示或要求二次确认。
- 每项必须解释性质、空间来源、可清理理由和清理影响。
- 不上传路径、文件名、依赖列表、项目结构或清理记录。
- 优先调用 `brew cleanup`、`pnpm store prune`、`xcrun simctl delete unavailable` 等官方工具。
- 开发者模式不读取源码内容，只统计依赖目录、lockfile 状态、缓存和构建产物。
